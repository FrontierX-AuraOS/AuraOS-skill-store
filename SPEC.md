# AuraOS Skill Specification v1.0

## Overview

A **Skill** is the smallest distributable unit in the AuraOS ecosystem. It contains:

| File | Required | Purpose |
|------|----------|---------|
| `MANIFEST.yaml` | ✅ | Metadata, permissions, entry points |
| `skill.md` | ✅ | Declarative definition (persona / actions) with YAML frontmatter |
| `main.py` | ❌ | Executable code, run in an isolated subprocess by the daemon |
| `icon.png` | ❌ | 256×256 PNG icon for the store |
| `README.md` | ❌ | Extended description shown on the skill detail page |

---

## MANIFEST.yaml Specification

```yaml
# ── Required ──────────────────────────────────
id: python-runner                    # Unique, kebab-case, matches folder name
name: Python Runner                  # Display name (max 64 chars)
version: 1.0.0                       # Semver
author: FrontierX                    # Publisher name
description: >-                      # One-liner (max 140 chars) for store cards
  Run Python scripts in a sandboxed environment with controlled tool access.

# ── Optional ──────────────────────────────────
license: MIT                         # SPDX identifier
homepage: https://example.com        # Project homepage
minAuraVersion: 0.1.2                # Minimum AuraOS version required
tags: [python, code, utility]        # Search tags (max 5)

# ── Permissions (if main.py exists) ────────────
permissions:
  tools:                             # Whitelisted tool names
    - say                            # Send a chat message
    - run_shell                      # Execute a shell command
    - read_file                      # Read a file from the user's drive
    - write_file                     # Write a file to the user's drive
  network:
    domains: [api.example.com]       # Allowed outbound domains (empty = none)
  filesystem:
    scope: skill                     # "skill" = own dir only, "drive" = user drive
  maxRuntimeSec: 30                  # Max seconds per invocation (default 30)

# ── Entry Point ────────────────────────────────
entry:
  type: python                       # python | markdown | both
  main: main.py                      # Relative path to entry script
  function: run                      # Function name to call (default: "run")
```

### Permission Model

Skills run in an **isolated subprocess** via `aura/skills/runner.py`. The `SkillContext` object is the **only** bridge to the daemon. Any operation not explicitly granted in `MANIFEST.yaml` is rejected.

| Permission | Scope | Default |
|------------|-------|---------|
| `permissions.tools` | Whitelist of tool names the skill can call | `[]` (none) |
| `permissions.network.domains` | Allowed outbound domains | `[]` (no network) |
| `permissions.filesystem.scope` | `skill` = own dir, `drive` = full user drive | `skill` |
| `permissions.maxRuntimeSec` | Hard timeout, process killed on exceed | `30` |

### Trust Tiers

```
untrusted  →  Fresh PR, no review           →  maxRuntimeSec: 5,  no network, tools: [say]
reviewed   →  CI passed, human approved     →  as declared in MANIFEST
verified   →  Official FrontierX skill      →  full trust, signed
revoked    →  Security issue found          →  removed from registry, clients auto-uninstall
```

## registry.json (Auto-generated by CI)

On every merge to `main`, CI regenerates the public registry:

```json
{
  "version": 1,
  "updated": "2026-08-04T12:00:00Z",
  "skills": [
    {
      "id": "python-runner",
      "name": "Python Runner",
      "version": "1.0.0",
      "author": "FrontierX",
      "description": "Run Python scripts in a sandboxed environment.",
      "tags": ["python", "code"],
      "downloadUrl": "https://raw.githubusercontent.com/FrontierX-AuraOS/AuraOS-skill-store/main/skills/python-runner",
      "iconUrl": "https://raw.githubusercontent.com/FrontierX-AuraOS/AuraOS-skill-store/main/skills/python-runner/icon.png",
      "installs": 0,
      "tier": "reviewed",
      "minAuraVersion": "0.1.2",
      "size": 24576,
      "checksum": "sha256:abc123..."
    }
  ]
}
```

The Aura client fetches this single JSON file to populate the Skill Store UI.  
Actual skill files are downloaded individually from `downloadUrl` when the user clicks "Install".

## skill.md Format (unchanged from current system)

```markdown
---
name: Python Expert
title_zh: Python 专家
title_en: Python Expert
category: 开发工具
category_en: Developer Tools
description: Helpful Python coding assistant
description_en: Helpful Python coding assistant
is_persona: false
tools: [say, run_shell, read_file]
---

You are a Python expert. Help the user write, debug, and run Python code.
```

The existing `load_skills()` in `aura/skills.py` continues to work as-is for `.md` files.

## CI Pipeline

```
PR opened
  ├── validate-manifests     ← YAML schema check
  ├── security-scan          ← Static analysis of .py files
  ├── sandbox-test           ← Run each skill in subprocess, verify permissions
  ├── generate-registry      ← Dry-run: would the registry build?
  └── diff-check             ← Did registry.json change unexpectedly?

PR merged to main
  ├── generate-registry      ← Rebuild registry.json
  ├── sign-skills            ← (Future) Sign with KMS key
  └── deploy-pages           ← (Future) Deploy store preview to GitHub Pages
```
