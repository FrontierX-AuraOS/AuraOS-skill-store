# AURA 文字冒险

`aura-text-adventure` 是 AuraOS 原生对话型第一层地牢冒险 Skill。核心游戏逻辑不依赖模型、网络、机器人运动或显示硬件；模型只负责把自然语言交给代码并组织代码已经产生的结果。

## 启动与继续

激活后说“开始冒险”创建新自动存档，或说“继续冒险”恢复自动存档。第一条消息会说明中心出生点、可见环境和合法操作。自然语言移动、观察、调查、开箱、状态/地图查询和战斗均走同一个 `run_skill_code` 入口。

## 第一层候选内容

第一轮采用以下待审阅的候选内容：队伍从 `(2, 2)` 的回声中庭出发；向西可沿不经过目标怪物的路径抵达旧军械库和宝箱；向北可抵达守门石像；向东可抵达下层石门。地图固定为完整 5×5，第二层仅声明入口，不包含第二层内容。

## 存档

存档位只有 `auto`、`manual_1`、`manual_2`、`manual_3`。SQLite 文件默认位于：

```text
~/.aura/skill-data/aura-text-adventure/saves.sqlite3
```

合法状态变化自动写入 `auto`。说“存档 1”写入手动档 1；覆盖已有手动档或删除存档必须确认。说“导出存档”会写入数据目录下的版本化 JSON；导入时先做版本和状态校验，失败不会覆盖原存档。

SQLite 使用标准库 `sqlite3`、WAL、事务和外键，不写入 Git 仓库、安装目录或发布包。Windows 与 RDK Linux 使用同一套代码和相对路径，设备之间不会自动同步。

## AURA 战斗

玩家普通攻击后，代码返回紧凑的 `AURA_DECISION_REQUIRED`，外层 Agent 必须用返回的单次令牌提交 `AURA_ACTION`。引擎验证动作、结算 AURA 和怪物，再返回 `TURN_RESOLVED`。未决期间查询、聊天、存档或退出不会结算回合；若先提交新的玩家行动，引擎用 AURA 普通攻击兜底完成旧回合，并拒绝执行该次新行动。模型不能修改伤害、生命、掉落或胜负。

## 降级边界

没有 ASR/TTS/屏幕时，完整文字主流程仍然可玩。语音和屏幕不建立第二套状态；`spoken_text` 来自同一个回合事件并已包含在可见输出中。AuraOS 上游 Agent 或云端模型完全不可用时，当前 Skill 没有独立入口，会如实报告聊天调度不可用。
